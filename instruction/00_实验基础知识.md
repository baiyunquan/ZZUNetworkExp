# **实验基础知识：Linux虚拟网络环境**

本套计算机网络实验基于Linux虚拟网络环境开展，选用openEuler操作系统（版本24.03及以上），核心依托Linux内核提供的网络命名空间（Network Namespace）实现虚拟网络环境的搭建与隔离。

## **【Linux命名空间概述】**

Linux命名空间（Namespace）是Linux内核原生提供的操作系统级资源隔离机制，是实现轻量级虚拟化的核心底层技术。其核心原理是对操作系统全局系统资源进行逻辑分区，为不同进程组构建相互独立的资源视图，使各组进程仅能感知和使用所属命名空间内的资源，无法访问、干扰其他命名空间及宿主机的全局资源，最终实现单操作系统内多组隔离运行环境的并行部署。

目前，Linux中定义了七种核心命名空间，每种命名空间针对性隔离一类系统全局资源，各司其职，共同构建完整的系统隔离体系，具体如下：

- **PID命名空间**：隔离进程标识空间。
- **挂载命名空间**：隔离文件系统挂载视图。
- **UTS命名空间**：隔离主机名与域名信息。
- **IPC命名空间**：隔离进程间通信资源。
- **网络命名空间**：隔离系统网络栈资源。
- **用户命名空间**：隔离用户与用户组ID。
- **Cgroup命名空间**：隔离控制组视图。

命名空间是容器技术中隔离能力的核心支撑，是容器实现环境独立的基础前提。基于Linux虚拟网络进行计算机网络实验，需要使用网络命名空间。

## **【Linux虚拟网络环境概述】**

Linux虚拟网络环境是依托网络命名空间，结合VETH对等设备、虚拟网桥等虚拟组件构建的纯软件仿真的网络环境，无需交换机、路由器、网线等任何物理网络设备，即可复刻与真实物理网络协议栈一致、转发逻辑一致、报文行为一致的网络运行场景。

Linux虚拟网络的核心原理为：通过网络命名空间的隔离能力，将宿主机唯一的全局网络协议栈切分为若干相互独立的逻辑网络空间，每一个网络命名空间均可等效为一台独立的物理主机，拥有全套专属网络资源，包含虚拟网卡、IP地址、子网掩码、路由表、ARP缓存、iptables防火墙规则及独立端口资源。

不同网络命名空间的网络配置完全独立、互不冲突。默认情况下，同一宿主机下多个虚拟节点无法直接互通，仅共享底层物理硬件资源。因此，为实现虚拟节点组网与数据传输，该环境需要依赖VETH对等设备、虚拟网桥等核心虚拟网络组件完成拓扑搭建。

- **VETH对等设备（VETH Pair）**：成对虚拟网卡设备，具备双向数据传输能力，可分别绑定两个不同的网络命名空间，用于实现点对点虚拟主机通信，是跨命名空间数据转发的基础载体。
- **虚拟网桥（Bridge）：软件模拟物理交换机的转发逻辑，可同时绑定多个VETH设备，实现多虚拟节点的局域网汇聚、数据交换与广播转发，用于搭建多主机局域网拓扑。**

## **【网络命名空间的管理】**

Linux系统提供ip netns专用工具集，实现网络命名空间的全生命周期管理，操作简洁、适配性强，是网络实验环境搭建的核心操作工具，基础核心管理操作如下：

- **创建网络命名空间：执行**`ip netns add`*`命名空间名`***命令，创建全新独立网络命名空间，系统会自动初始化默认回环网卡lo与空网络配置。**
- **查询命名空间：执行**`ip netns list`**命令，查看当前系统所有已创建的网络命名空间，确认环境部署状态。**
- **进入命名空间执行操作：执行**`ip netns exec`*`命名空间名 指令`***，在指定命名空间中执行网络配置、状态查看等单条指令；执行**`ip netns exec`*`命名空间名`*`bash`**，可以进入指定命名空间中，连续执行多条指令，通过**`exit`**可以退出指定命名空间。**
- **删除命名空间：执行**`ip netns del`*`命名空间名`***，删除无用网络命名空间，释放系统资源，操作可逆、环境可快速重置。**

同时，系统内核会在`/proc/[PID]/ns/net`路径记录进程所属网络命名空间标识，可通过节点唯一性判断不同进程的网络隔离归属，实现精细化的网络环境管控。

## **【虚拟网络组件的使用】**

Linux中的虚拟网络组件VETH Pair和Bridge均可以依托Linux系统的`ip`系列命令实现配置与管理。这两类虚拟组件的用法如下：

**（1）VETH对等设备（VETH Pair）核心用法**

- **创建VETH虚拟网卡对**：执行命令`ip link add veth0 type veth peer name veth1`，创建成对绑定的虚拟网卡veth0与veth1，两端默认互通，作为跨命名空间数据传输链路。
- **绑定至指定网络命名空间**：分别将两端网卡划入不同虚拟节点，实现节点链路对接，命令为`ip link set veth0 netns 命名空间1`、`ip link set veth1 netns 命名空间2`。
- **启用网卡并配置IP地址**：进入对应命名空间后，依次执行`ip link set dev veth0 up`开启网卡，执行命令`ip addr add 192.168.1.1/24 dev veth0`配置IP地址，完成点对点通信基础配置。
- **删除VETH设备**：如需重构拓扑，或实验已结束，可执行命令`ip link del veth0`，即可同步删除成对的VETH虚拟设备。释放系统资源。

**（2）虚拟网桥（Bridge）核心用法**

- **创建虚拟网桥**：执行`ip link add br0 type bridge`命令，创建名为br0的虚拟网桥，模拟物理交换机转发功能。
- **启用网桥设备**：执行`ip link set dev br0 up`命令，启动网桥br0，使其具备数据交换与广播转发能力。
- **绑定VETH设备至网桥**：将多个虚拟节点的VETH网卡（如veth0、veth1）接入网桥br0，实现多节点局域网组网，命令为`ip link set veth0 master br0``和``ip link set veth1 master br0`。
- **列出网桥设备中绑定的网络接口**：执行`ip link show master br0`命令，或执行`bridge link show br0`命令，可以列出网桥br0中已绑定的所有网络接口。
- **解绑与删除网桥**：如需重构拓扑，或实验已结束，可先执行`ip link set veth0 nomaster`命令解绑网卡，再执行`ip link del br0`命令删除虚拟网桥。

通过上述IP命令，可快速完成虚拟链路搭建、局域网汇聚、网络参数配置等操作，灵活适配各类计算机网络实验拓扑的快速构建与迭代调试。

## **【Linux虚拟网络环境的构建方法和步骤】**

依托网络命名空间的隔离能力，结合VETH对等设备、虚拟网桥两类核心虚拟组件，可以模拟主机、路由器、交换机等网络设备，进而构建Linux虚拟网络环境。

**（1）网络设备模拟方法如下：**

- **主机和路由器：**使用一个网络命名空间模拟主机，添加并绑定VETH对等设备与其他设备相连，配置IP地址和路由使主机和路由器具有网络通信能力。
- **交换机：**使用一个网络命名空间模拟交换机，在交换机的命名空间内部创建bridge，将需要连接到交换机的网络接口（VETH对等设备）绑定到bridge，实现这些接口之间的二层转发。

**（2）构建Linux虚拟网络环境的操作步骤如下：**

- **创建独立网络节点：**根据实验需求创建多个独立网络命名空间，作为虚拟网络中的路由器、交换机和主机节点，每个节点拥有独立网络栈，实现初始网络节点构建。
- **创建bridge：**在交换机节点内部，创建虚拟网桥，实现交换机构建。
- **构建虚拟通信链路：**创建VETH对等设备，将设备两端分别绑定至不同网络命名空间，实现节点的点对点通信；对于需要通过交换机互连的节点，将所有节点的VETH设备接入bridge，完成局域网拓扑搭建。
- **配置网络参数：**为各网络命名空间内的虚拟网卡配置独立IP地址、子网掩码，设置默认路由与网关，同时启用网卡并开启网卡转发功能，确保跨节点、跨网段数据正常传输。**注意：**交换机bridge内部的虚拟网卡不需要配置IP地址。
- **调试、验证与实验：**通过ping、traceroute等指令测试节点连通性，通过Linux中的各种网络工具配置防火墙规则、修改路由表，模拟网络故障、路由切换等实验场景，利用Wireshark抓包软件分析网络数据流。

通过上述方法和步骤，可灵活搭建多种网络拓扑，复刻真实物理网络的协议交互与数据传输逻辑，进行计算机网络实验。

## **【计算机网络实验环境】**

计算机网络实验采用openEuler系统，支持两种运行环境，分别为VMware虚拟机环境和真实Linux环境，两者在运行机制、操作体验和适用场景上存在差异，实验者可根据自身硬件条件和操作需求选择。

**（1）VMware虚拟机环境**

VMware虚拟机环境是计算机网络实验的推荐环境，适用于大多数实验者，尤其是Windows或macOS系统用户。该环境通过VMware虚拟化软件，在宿主机操作系统之上模拟出独立的硬件环境，将openEuler系统安装在虚拟机中，然后在虚拟机内部搭建基于网络命名空间的虚拟网络。推荐使用VMware Workstation 17以上版本。

VMware虚拟机环境的核心特点：一是兼容性强，不受宿主机操作系统限制，Windows、macOS均可搭建，无需对宿主机进行系统改造；二是隔离性极强，虚拟机与宿主机、虚拟机与其他虚拟机之间完全隔离，实验过程中出现的系统故障、配置错误仅影响当前虚拟机，不会损坏宿主机数据或系统环境；三是便捷性高，可通过虚拟机快照功能快速保存实验状态，便于实验回溯、故障恢复，且硬件配置（CPU、内存、磁盘）可灵活调整，适配实验需求；四是有轻微性能损耗，由于虚拟机运行需经过虚拟化层翻译调度，其CPU、内存和磁盘I/O性能略低于真实Linux环境。

**（2）真实Linux环境**

真实Linux环境指将openEuler系统直接安装在物理计算机中，无需通过虚拟化软件，直接在物理系统中搭建基于网络命名空间的虚拟网络。

真实Linux环境的核心特点：一是性能无损耗，系统直接与物理硬件交互，无虚拟化层带来的性能消耗，网络响应速度、资源调用效率优于虚拟机环境，适合对性能要求较高的复杂网络实验；二是硬件支持完整，可直接调用物理网卡、USB设备等硬件资源，适配需要硬件交互的实验场景；三是操作风险较高，实验过程中的错误配置可能导致系统崩溃，数据丢失风险高于虚拟机环境；四是资源分配固定，硬件配置受物理计算机限制，无法灵活调整，且无法通过快照功能快速恢复实验状态，实验回溯难度较大。

## **【计算机网络实验软件需求】**

进行计算机网络实验，需要确保openEuler操作系统中已安装以下软件：

- **ukui：**简洁的桌面图形环境，为 openEuler 提供可视化操作界面，方便实验中直观操作终端、浏览器和抓包工具**。**

**安装命令：**`dnf install ukui`。

- **kylin-screenshot：**截图工具，openEuler已默认安装。

安装命令：`dnf install kylin-screenshot`。

- **iproute2：iproute2是软件项目名，在openEuler系统中，软件安装包名为iproute。iproute2是Linux**系统的新一代网络工具集，集成ip、tc、routel等命令。其中，ip用于虚拟网络设备创建、网卡配置、路由与地址管理；tc是流量控制工具，依托netem模块可实现带宽管控、延迟、丢包等网络损伤仿真；routel为路由查看辅助脚本，对`ip route`命令输出的路由信息进行格式化对齐展示，便于直观阅读内核路由表，适合网络拓扑调试。iproute2工具集是完成计算机网络实验的必备工具，openEuler已默认安装。

安装命令：`dnf install iproute`。

- **Wireshark**：专业网络抓包分析软件，可捕获、解析各类网络数据包，直观观测TCP、IP等协议交互过程，是完成计算机网络实验的必备工具。

安装命令：`dnf install wireshark`。

- **traceroute：跟踪路由工具，可以跟踪观察数据包的转发路径，用于调试网络环境，**是完成计算机网络实验的必备工具。

安装命令：`dnf install traceroute`。

- **nmap：**跨平台网络探测、安全扫描工具套件**，包括ncat、nping等工具。其中，ncat**是增强版netcat工具，集成端口监听、TCP/UDP连接与进程执行等功能，用于网络数据交互、简易shell反弹等；nping可构造TCP/UDP/ICMP/ARP等报文，用于自定义报文发包。nmap是完成计算机网络实验的必备工具。

安装命令：`dnf install nmap`。

- **truncate：**放大或缩小文件到指定字节长度，也可以创建指定长度的新文件，该工具属于Linux核心工具包，是完成计算机网络实验的辅助工具，openEuler已默认安装。
- **bird：**开源动态路由协议软件，支持RIP、OSPF、BGP等主流内部网关与外部网关路由协议，能够在Linux主机或网络命名空间上搭建路由节点，实现动态路由信息交互、路由学习与路由分发，是完成计算机网络实验中路由协议实验的必备工具，openEuler的软件仓库中提供bird 2.x版本的安装包。
- 安装命令：`dnf install bird`。
