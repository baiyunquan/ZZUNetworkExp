# 实验5：TCP可靠传输和重传分析

## 【实验目的】

本实验核心目的是帮助实验者深入掌握TCP可靠传输的核心原理，理解TCP保障数据可靠传输的关键机制；熟练掌握TCP超时重传、快重传的触发条件、工作流程与核心作用，理解TCP重传机制的应用场景。

此外，实验通过人为模拟网络丢包场景，结合抓包数据分析，帮助实验者掌握Linux系统参数配置、丢包规则配置方法，进一步夯实TCP协议理论基础，培养网络异常场景下的协议分析与故障排查能力。

## 【实验内容】

基于openEuler操作系统，利用“网络拓扑助手”智能体辅助编写自动化脚本，完成实验环境搭建；通过修改Linux系统内核参数、关闭主机的SACK重传机制，搭建受限的TCP传输环境；利用tc工具在路由器节点配置随机丢包规则，模拟真实网络丢包异常场景；通过ncat工具搭建TCP服务端与客户端，完成大文件跨主机TCP传输；使用Wireshark抓取全过程数据包，筛选TCP流量，重点分析TCP超时重传、快重传、部分ACK等核心机制的报文特征，验证TCP可靠传输的核心特性。

## 【实验拓扑】

**本实验与实验3、实验4采用相同的网络拓扑，**需要构建包含两台主机、两台交换机和三台路由器的网络拓扑，如图5.1所示。

主机H56A通过交换机SW56A与路由器RB相连，主机H57C通过交换机SW57C与路由器RD相连，主机H56A访问主机H57C的数据包，传输路径需依次经过路由器RB、RA、RD。

所有设备均配置IPv4协议栈，各节点固定IP规划如下：

(1) 主机H56A：192.168.56.126/25；主机H57C：192.168.57.254/26。

(2) 路由器RB连接SW56A接口：192.168.56.1/25；RB与RA的互连网络：192.168.56.244/30，两端接口的IP地址采用这个/30地址块中的可用地址。

(3) 路由器RD连接SW57C接口：192.168.57.193/26；RD与RA的互连网络：192.168.56.252/30，两端接口的IP地址采用这个/30地址块中的可用地址。

本实验拓扑主要关注端到端通信，连接路由器的两个网络的配置允许调整，完成设备IP配置与静态路由部署后，可实现两台主机的跨网络TCP通信。为规避网卡硬件运算对实验结果的干扰，实验中需关闭网卡offload功能，保证IP分片、TCP校验和等计算均由CPU完成。

## 【实验步骤】

本节以openEuler 24.03-LTS版本为例，详细讲解系统参数配置、虚拟拓扑搭建、网络丢包模拟、TCP文件传输、Wireshark抓包分析的完整流程，实验者需按序完成每一步，确保操作无误后再进行下一步。

**步骤1：环境检查**

(1) 确保已切换至root用户。若未切换，打开终端，执行su - root，输入管理员密码完成权限切换，保证后续网络配置、工具调用权限充足。

(2) 确保基础软件工具已安装。执行ip -V、wireshark --version等软件版本查询命令，确认iproute2、nmap、traceroute、Wireshark、truncate工具安装正常，可正常调用。

(3) 确保系统防火墙已关闭。执行systemctl status firewalld查看防火墙软件状态，若未关闭，执行systemctl stop firewalld关闭防火墙，避免虚拟路由器重组IP分片。

**步骤2：借助AI工具，搭建虚拟网络拓扑并验证**

(1) 借助“网络拓扑助手”，编写bash脚本。

可以直接采用实验3或实验4的网络拓扑脚本程序，也可以在“网络拓扑助手”界面，输入提示词，描述本实验网络拓扑，由“网络拓扑助手”智能体创建脚本程序，并给出使用方法。

(2) 按照“网络拓扑助手”智能体给出的说明，执行脚本并创建实验网络拓扑。

```bash
# 修改脚本权限后，在脚本保存目录内，执行脚本程序
./create_topology.sh create
```

(3) 验证实验网络拓扑和配置并记录。

```bash
# 验证命名空间
ip netns list
# 在各命名空间内，分别验证网络接口（遍历上一步得到的命名空间名）
ip netns exec H56A ip link show
ip netns exec ……
# 在交换机命名空间内，验证网桥接口绑定（遍历上一步得到的网桥名）
ip netns exec SW56A bridge link show br_SW56A
ip netns exec ……
# 在各主机和路由器命名空间内，验证IPv4地址配置（遍历主机和路由器的命名空间名）
ip netns exec H56A ip addr
ip netns exec ……
# 测试主机H56A到主机H57C的可达性
ip netns exec H56A ping -c 4 192.168.57.254
# 测试主机H56A到主机H57C的转发路径
ip netns exec H56A traceroute 192.168.57.254
```

若验证结果不满足实验拓扑，可以将验证和测试结果粘贴给“网络拓扑助手”智能体，请求智能体修改网络拓扑脚本。重新创建网络拓扑，验证通过后，再进行后续步骤。

记录你创建的实验拓扑中，主机、交换机和路由器的命名空间（NS）名称、NS内VETH接口名称、VETH接口的IP地址（若有）、VETH接口的MAC地址、VETH接口的对端接口名称和所属NS名称。

注意：每次重新执行脚本，创建的VETH接口MAC地址有可能不同。

(4) 验证网卡offload相关功能已关闭。

```bash
# 在指定命名空间中，查看指定网卡的offload功能状态（本实验要求遍历所有主机，验证所有VETH网卡的offload状态，ve_H56A应替换为你的网络接口名）
ip netns exec H56A ethtool -k ve_H56A | grep -E &quot;checksum|generic&quot;
ip netns exec ……
```

本实验要求接收校验和卸载（rx-checksumming）、发送校验和卸载（tx-checksumming）、GSO通用分段卸载（generic-segmentation-offload）的状态为off。

**步骤3：配置路由器丢包规则，模拟网络异常**

**本实验利用tc工具，依托netem模块，在路由器RA上配置随机丢包规则，模拟真实网络传输丢包异常，触发TCP重传机制。**

**执行以下命令，设置路由器RA内部连接路由器RD的VETH网络接口，以10%概率丢包。路由器RA中的接口名应根据你的网络拓扑确定，本例中接口名为ve_RA_RD。**

```bash
# 在RA命名空间配置随机丢包规则
# 先清理旧规则，防止多层qdisc叠加
ip netns exec RA tc qdisc del dev ve_RA_RD root
# 挂载netem，所有ve_RA_RD接口向外发送的报文以10%概率随机丢包
ip netns exec RA tc qdisc add dev ve_RA_RD root netem loss 10%
```

**清理旧规则时，如果从来没有添加过规则，则会报错**Cannot delete qdisc with handle of zero**，该错误可忽略。**

**配置完成后，执行**ip netns exec H56A ping -c 20 192.168.57.254**命令，发送20个途经RA的数据包，测试丢包规则是否生效。**

**补充说明：Linux中，也可以利用iptables设置规则，在用户态模拟网络丢包。**

**步骤4：模拟两台主机终端环境，并修改两台主机的TCP内核参数**

(1) 新建第一个终端窗口，设置终端窗口标题为“H56A”，执行ip netns exec H56A bash命令，将当前终端模拟为H56A主机终端，后续H56A上的所有命令均在该主机模拟终端中执行。如需退出模拟终端环境，执行exit命令即可。

(2) 新建第二个终端窗口，设置终端窗口标题为“H57C”，执行ip netns exec H57C bash命令，将当前终端模拟为H57C主机终端，完成两台主机模拟终端环境搭建。

**(3) 在两台主机的虚拟终端中执行**sysctl -w net.ipv4.tcp_rmem='4096 65536 65536'**命令，修改系统参数，调整TCP接收缓存，降低主机接收窗口大小，方便观测重传现象。**

**(4) 在两台主机的虚拟终端中执行**sysctl -w net.ipv4.tcp_sack=0**命令，修改系统参数，关闭SACK选项，避免执行基于SACK的重传算法，保证实验观测结果单一。**

**步骤5：在H56A上创建测试文件**

在主机H56A的模拟终端中，执行truncate -s 100K 100K_56A.dat命令，创建一个长度为100K字节的测试文件，保证数据量足够触发重传，命名为100K_56A.dat。该文件将作为TCP数据传输的载荷，用于后续TCP实验。

**步骤6：在H56A上，开启Wireshark抓包**

(1) 新建另一个终端窗口，执行ip netns exec H56A wireshark &命令，后台启动H56A主机环境下的Wireshark抓包工具。

(2) 在Wireshark界面中，选中H56A主机上的VETH虚拟网卡接口，启动抓包，用于抓取和观察后续TCP通信数据包。

**步骤7：搭建TCP服务端与客户端，并传输测试文件**

(1) 在主机H57C的模拟终端中，执行ncat -lv 4499 > 100K_57C.dat命令，开启TCP服务端程序，监听4499端口，并采用输出重定向方式，将接收的所有数据保存至本地文件100K_57C.dat中。

(2) 在主机H56A的模拟终端中，执行ncat 192.168.57.254 4499 < 100K_56A.dat命令，启动TCP客户端程序，连接H57C主机的4499端口，建立TCP连接，并采用输入重定向方式，读取本地测试文件100K_56A.dat，通过TCP连接持续发送。

(3) 文件传输完毕后，客户端会自动终止TCP连接。

**步骤8：数据包分析和实验报告撰写**

停止Wireshark抓包，保存完整抓包文件，筛选TCP协议报文，详细分析TCP通信过程，识别超时重传、快重传报文，分析两种重传机制的触发时机、序号与确认号变化规律，以及部分ACK报文的特征，整理实验截图与分析数据，完成实验报告撰写。

**补充说明：**

(1) 如果抓包结果不理想，比如未捕获到超时重传、未捕获到快重传、未捕获到部分ACK等，可以重复步骤6-7重新实验，直至抓到满足要求的数据。

(2) 如果多次重复步骤6-7进行实验，抓包结果仍然不理想，可以调整步骤4中的丢包概率，然后再重新实验，直至抓到满足要求的数据。
